# Workbench test data — edge cases

Two CSVs generated by `generate_test_data.py` (seeded, reproducible):

- **`workbench_temporal_test.csv`** — the time-series *data file* (1521 rows). Upload this as the data file on Step 1.
- **`workbench_soil_site_test.csv`** — per-plot soil + site data (16 rows, one per plot). See "Two-file note" below.

## Temporal file — suggested mapping

| CSV column | Map to | Notes |
|---|---|---|
| `DateTime` | **Measurement date** | pick date format **MM/DD/YYYY (US)** — values include a time part |
| `Treatment` | **Treatment identifier** | 4 codes → give readable names on Soil step (e.g. CT-U → "Conventional till + urea") |
| `Block` | **Replication / plot identifier** | mapping this + Treatment triggers replicate averaging |
| `N2O_flux_ugN_m2_h` | **N₂O flux** | unit = **µg N/m²/h** (non-canonical → tests conversion + mandatory unit) |
| `SoilVWC_pct` | Volumetric water content | (no unit choice — %) |
| `SoilTemp_C` | Soil temperature | unit °C |
| `AirTemp_C` | Air temperature (avg) | unit °C |
| `Precip_mm` | Precipitation | unit mm |
| `SoilNH4_mgN_kg` / `SoilNO3_mgN_kg` | Soil ammonium / nitrate | |
| `N_applied_kgN_ha` | *(optional)* Nitrogen application event | unit kg N/ha — if mapped, the **Fertilization** timeline section is marked "provided by data" |
| `DOY` | *leave unmapped* | DOY is derived; it won't appear as a target (tests non-mappable) |
| `Notes` | *leave unmapped* | free text (leftover column) |

## What each edge case exercises

| Edge case in the data | Expected behavior |
|---|---|
| 4 treatments (CT-U/NT-U/CT-C/NT-C), 4 blocks | replicate averaging → one row per treatment×date; N₂O flux **standard error** computed across reps |
| Sub-daily rows (`auto-chamber`, 4×/day on 6 dates) | **time-weighted daily average**; Review shows "…time-weighted daily average (using your timestamps)…" |
| Missing replicates on ~10 date/treatment combos | averages what's present; single-rep dates get no SE |
| 8 rows with a blank `Treatment` | readiness gate + Review banner: "8 row(s) have a blank treatment cell" |
| 3 unparseable dates (`late June 2023`, etc.) | bad-date gate + Review banner naming the values |
| US datetime `MM/DD/YYYY HH:MM` (day>12 present) | format guess pre-selects MM/DD/YYYY; datetimes parse; time stripped on single-point days |
| Non-canonical flux unit (µg N/m²/h) | must pick a unit to continue; values convert to g N/ha/d for storage |
| Irregular sampling with gaps | daily-fill between first/last date |
| `N_applied` only on fertiliser dates | if mapped → Timeline Fertilization section shown as "provided" (no prompt) |

## Two-file note (soil/site CSV)

The workbench takes **one** data file (the time-series). It has no complementary
second-file import — uploading a second data file **replaces** the first's parsed
content. So `workbench_soil_site_test.csv` is here to:

1. see how the parser/preview handles a per-plot table, and
2. serve as the reference values you'd hand-enter on the **Soil & Management** step
   (soil texture/pH/BD/SOM vary by plot — the "treatment-average from CSV" auto-fill is
   a deferred future feature; for now enter treatment-level values manually), and the
   **Site** step (Latitude/Longitude/MAP/MAT/SiteName/Country — constant across rows).

To exercise the soil columns *inside* the temporal flow instead, you could paste the
soil columns into the temporal file per plot; they'd then appear as leftover columns.
